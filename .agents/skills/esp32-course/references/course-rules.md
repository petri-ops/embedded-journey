# 课程规范细则

## 课程体系（已定路线，顺序教学）

课程表与状态以 `esp32-course/00-课程总览.md` 为准，规划路线：

1. 电子电路基础（✅ 已讲授，待作业）
2. GPIO 输入——按键与中断（✅ 已讲授，待实操）
3. ADC 与 PWM 进阶（配件：摇杆、光敏、LM35、声音传感器、舵机、无源蜂鸣器、步进电机）
4. 通信协议 UART / I2C / SPI（配件：OLED、LCD1602、240×240 屏、矩阵键盘）
5. 网络进阶——MQTT 与 asyncio（配件：任一传感器 + 继电器）
6. 结业项目（候选：PIR 安防、干簧管门磁、超声波测距尺、红外遥控舵机云台）

## 开课模板

每课按固定六步走：

1. **为什么学**：这课解决什么真实问题（结合用户已有的项目，如网页控灯）
2. **原理**：最小必要的理论，多用表格和类比；能引用前面课程的概念就复用
3. **实操**：step-by-step，先接线图/引脚表（核对 hardware.md 红线），再代码
4. **小项目**：组合本课 + 之前技能，做一个完整能跑的东西
5. **作业**：每次 1 个，量小可完成，下节课开始时批改
6. **归档**：按会话结束四件事执行（笔记 + 课程表/日志 + 成长档案 + HTML）

## 文件规范

- 笔记：`esp32-course/NN-主题.md`，NN 两位数字递增（01、02…）；同目录运行 `python build_html.py` 生成同名 HTML
- 代码：`esp32/*.py`，小写英文命名，文件顶部注释写用途、接线、运行方式
- 固件：`firmware/` 只放 bin 备份
- 进度、学习日志、踩坑：只写在 `00-课程总览.md`，不要在别处另立进度表（避免两处不一致）

## 作业批改标准

1. 读代码（`esp32/` 下）或听用户描述运行结果
2. 通过条件：能跑 + 达到题目要求
3. 通过：更新课程表状态，指出 1-2 个可选的改进点
4. 不通过：指出具体问题（带原因，联系课程原理），给出最小修改提示而不是直接改完

## 教学原则

- 先原理后代码：让用户理解"为什么"，而不是复制能跑的代码
- 踩坑即教材：任何异常（Brownout、连不上、重启）都复盘到根因，并记录到踩坑表
- 每课控制在一次会话能讲完的量；概念多了就拆下一课
- 术语链接规范：领域术语在讲义中首次出现时链接 `词汇表.md#锚点`（锚点用英文小写连字符），并在 `词汇表.md` 补对应词条（格式：`- <a id="锚点"></a>**术语（English）** —— 通俗解释。`）；构建脚本自动转为点击悬浮解释卡
