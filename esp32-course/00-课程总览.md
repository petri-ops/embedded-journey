# ESP32 + MicroPython 学习课程

> 学习方式（2026-10-26 起）：讲义网站自学 → 实操验证 → 交作业由 AI 助手批改 → 归档自动更新网站
> 课程管理：本项目由 `.agents/skills/esp32-course` 技能驱动（说"上课 / 下一课 / 看进度 / 交作业 / 记录踩坑"即可）
> 硬件：ESP32-S3 开发板（第三方 N16R8 双 Type-C：16MB Flash + 8MB PSRAM，原生 USB + CH343P，端口号不固定）｜ 配件：进阶版套件 36 项（见 [配件清单](配件清单.md)）
> 固件：MicroPython v1.29.0（S3 Octal-SPIRAM + XMC 启动补丁，见踩坑表 10-27）｜ 串口：COMx（会变，以设备管理器为准）｜ 旧板已判废，详见 `hardware.md`

> 📄 **文档格式说明**：每课同时保存 `.md`（编辑源码）和 `.html`（分享版）。
> `.html` 是单文件、无依赖，双击浏览器打开即可，也可直接发给朋友。
> 修改 `.md` 后在本目录运行 `python build_html.py` 重新生成。

## 常用命令备忘

```bash
# 查串口（端口号会变：运行态 PID_4001，下载模式 PID_1001）
powershell -NoProfile -Command "[System.IO.Ports.SerialPort]::GetPortNames()"

# 上传文件到板子 / 重启 / 直接运行本地脚本（COMx 换成实际端口）
python -m mpremote connect COMx cp D:/1.WorkDir/PLC/esp32/station_main.py :main.py
python -m mpremote connect COMx reset
python -m mpremote connect COMx run D:/1.WorkDir/PLC/esp32/seg.py

# 健康检查：能打印出芯片信息就说明固件在跑（没反应先查端口/是否停在下载模式）
python -m mpremote connect COMx exec "import sys,machine,esp; print(sys.implementation._machine, machine.freq(), esp.flash_size())"

# 烧录固件（S3：先按住 BOOT 点 RST 进下载模式，或 REPL 里 import machine; machine.bootloader()）
python -m esptool --port COMx erase-flash
python -m esptool --port COMx --baud 460800 write-flash 0x0 D:/1.WorkDir/PLC/firmware/ESP32_GENERIC_S3-SPIRAM_OCT-20260824-v1.29.0-xmc207018.bin
```

## 项目门户 v4（core + features）

- 网页（局域网）：**http://mpy-esp32s3.local/**（固件自带 mDNS）或 http://192.168.0.100/
- 定位：**控制 + 呈现 + 交互**，不是开发平台；代码/Git/构建仍在 PC
- 架构：`station/core.py`（WiFi/NTP/状态/命令/日志/看门狗）、`web.py`（独立线程 + 通用 UI/API）、`mqtt_link.py`（独立线程 + 聚合状态/命令）、`features/`（system/led/boot/network/weather/log）
- **Feature 契约**：`id/title/order/fields/card_fields/actions/list_key/has_loop` + `init/status/command/loop`；新增功能 = 加一个 feature 文件 + 注册，网页卡片/详情/API/MQTT 自动带上（扩展指南 `esp32/station/README.md`）
- 页面：动态卡片、点击详情（网络扫描/天气刷新在打开详情时自动执行）、控制动作（LED 开关/PWM）、日志图表/表格/下载、在线自动重试
- API：`/api/features`、`/api/status`、`/api/cmd?feature=led&action=pwm&value=512`、`/api/logs`、`/download`
- MQTT：前缀 `petri/lab-0172ea`；状态 `<prefix>/status` 聚合 JSON；命令 `<prefix>/cmd` 格式 `feature:action[:value]`（`led:on`、`led:pwm:512`、`network:scan`、`weather:refresh`、`log:now`），兼容旧 `on/off/pwm`；ACK `<prefix>/ack`
- 公共 broker 偶发 `err` 只影响 MQTT，网页不受影响；要稳定换私有 broker
- 天气：中国天气网镜像（免 key），杭州 `101210101`；NTP：`ntp.aliyun.com`（UTC+8）；CSV：`/data/log.csv`
- 板载感知：MCU 温度、WiFi RSSI/邻居、BOOT 键；**没有**环境温湿度/光照/PIR/IMU
- BLE：暂未作为 feature 启用（GATT 连接会拖垮 WiFi，后续单独 feature）
- 自恢复：`main.py` 自启；web/MQTT 各自线程；`net_task` 重连 WiFi；看门狗 120 秒；断电恢复后自动重连，主题和 CSV 不变
- 供电：5V 充电器可 24 小时跑；电脑 USB 供电时电脑关机=断电，恢复后自动重启并重连
- 地址：mDNS 名字不变（设备支持 `.local` 即可，无需固定 IP）；PC 若挂代理需把 `*.local` 加入绕过
- 部署：上传 `station/` + `station_main.py`（为 `main.py`）；回滚：上传 `remote_station.py` 为 `main.py`

## 踩坑记录（持续补充）

| 日期 | 现象 | 原因 | 教训 |
|------|------|------|------|
| 10-22 | CP2102 无 COM 口 | 驱动未安装（错误码 28） | Windows Update 自带官方驱动 |
| 10-22 | Thonny 刷机"没反应" | 固件家族选错 + 未点安装 | 家族必须选 ESP32（经典款） |
| 10-22 | REPL 连不上板子 | 出厂固件不是 MicroPython | 先刷固件再连 REPL |
| 10-22 | 数码管接上后无限重启 | 段脚未限流，3.3V 被拉垮触发 Brownout | GPIO 驱动 LED 必须串 220Ω+ 电阻 |
| 10-26 | 拔掉数码管后板子仍反复 Brownout：轻负载（下载模式/空片）正常，重负载（固件启动+WiFi）必崩 | 短路冲击烧伤板载 3.3V 稳压器（LDO），供电能力永久衰退，板子判废 | 短路不止"当时重启"，会造成**永久硬件损伤**；硬件诊断三板斧：①裸板测试 ②换线换口排除供电 ③空片启动对比轻重负载定位损伤 |
| 10-27 | 新板 ESP32-S3 刷官方固件无限重启：`bootloader_flash: XMC flash startup fail` → `failed when running XMC startup flow, reboot!` | IDF v5.5.2 只把 XMC 型号字节 0x40/0x41/0x50 当合法芯片；本板 Flash RDID 为 `20 70 18`（型号 0x70），复查误判失败 | 补丁把 bootloader 该失败分支返回值改为 ESP_OK 并重算 checksum/SHA256（脚本 `firmware/patch_xmc_207018.py`，镜像 `...-xmc207018.bin`）；启动日志仍会打印该 E 行，属预期。教训：手改二进制务必核对字节序——昨晚把 `7C F2` 改成 `02 0C`（应为 `0C 02`），直接 IllegalInstruction |
| 10-27 | 从下载模式回应用后，COM10 报"被其他程序占用"，重启 USB 设备也无效 | Windows 对已绑定 COM 号的 USB CDC 保留了旧句柄 | 用 `pnputil /disable-device` + `/enable-device` 强制重新枚举（实例 ID 以设备管理器为准），端口会变号；仍不行再物理拔插 |
| 10-27 | 板子 `main.py` 自启后 USB 串口消失，设备管理器显示 `CM_PROB_DISABLED` | 之前 `pnputil` 禁用/启用 USB 时只完成了禁用（shell 权限不足，enable 失败） | 管理员权限执行 `pnputil /enable-device <实例ID>`；本机 UAC 已关，可用 `Start-Process -Verb RunAs` 无提示提权。WiFi/MQTT 不受影响 |
| 10-27 | 网页 `fetch('/api/status')` 报 `ERR_CONNECTION_RESET`，curl 也 reset | HTTP 处理只读了请求行，没读请求头；关闭连接时内核因未读数据发 RST | 响应前把请求头读到空行，再关闭连接 |
| 10-27 | CSV 日志每次只剩一行，不累积 | `ensure_log` 用完整路径 `/data/log.csv` 和 `os.listdir` 的 `log.csv` 比较，永不相等，每次用 `"w"` 重写 | 用 `os.stat(LOG_PATH)` 判断文件是否存在 |
| 10-27 | BLE GATT 连接后 WiFi/网页/MQTT 一起掉线 | ESP32-S3 MicroPython NimBLE 与 WiFi 共存 + 高负载；仅广播稳定，连接不稳 | BLE 默认关闭；需要时单独开启，不与 24/7 网页同时用 |
| 10-27 | 网页刷新偶尔断、等一会又恢复 | 网页服务和 MQTT/网络阻塞在同一 asyncio 循环，被拖死 | 网页与 MQTT 各自独立线程；前端 3 秒自动重试；Web 服务器不再受 MQTT 抖动影响 |
| 10-27 | 文档写"MQTT QoS1 + ping 自恢复"，但新旧两版代码（`remote_station.py` 与 `station/mqtt_link.py`）的 publish/subscribe 均未传 qos 参数，实际一直跑 QoS0，也没有 PINGREQ 探测 | umqtt.simple 默认 qos=0；v3/v4 演进中丢了设计参数或文档先行 | umqtt.simple 支持 qos=1 发布（阻塞等 PUBACK），给 STATUS/CMD 加上即同时获得送达保证与活性探测；未定案前文档按 QoS0 描述 |
